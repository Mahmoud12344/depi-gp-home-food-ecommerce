## 2. Root Causes of Regressions (Grouped by Pattern)

### Pattern 1: Rewritten Markup Instead of Unrolling `main`'s Exact Partials
Instead of copying `main`'s exact HTML/Tailwind markup from `Views/*/Partials/_*.cshtml` into each destination `Views/<Controller>/<Action>.cshtml` and unrolling the `x-for` loops in place, the migration subagents wrote brand-new HTML layouts from scratch. This caused widespread layout regressions:
- **Browse Dishes (`/Dishes`) & Browse Chefs (`/Chefs`)**: `main` uses a full-width page with a **sticky horizontal control bar** (`search + category dropdown + sort dropdown + Filters drawer trigger + Grid/List switcher`) above a full-width 3-column card grid (`grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6`). The migrated views replaced this with a 2-column left-sidebar layout (`w-full lg:w-72 shrink-0`), shrinking the card area and breaking card proportions.
- **Dish Details (`/Dishes/Details/1`)**: `main` uses a custom `.dish-detail-grid` (`36.5%` / `63.5%` split with `64px` gap) where the left column is a **690px 3D vertical stacked card gallery** (`.dish-gallery-frame-690` + `.dish-photo-card-420-520`) and the right column contains the dish header, 2-column info cards (`Chef` + `Prep Time`), inline customization option groups, 200-char special note textarea, quantity stepper + `Add to Cart` + `Heart` button, and **3 collapsible accordions** (`Description`, `Ingredients`, `Serving & Preparation`). The migrated view replaced all of this with a standard `grid-cols-1 lg:grid-cols-12` layout, a flat `aspect-[4/3]` static image, a separate full-width tabs card below, and a separate review submission form.
- **Public Chef Profile (`/Chefs/Details/1`)**: `main` uses a floating overlapping profile card (`-mt-24 relative z-10`), a `grid-cols-2 md:grid-cols-4` stats strip inside the profile card, an inline search + category filter bar, 2-column horizontal dish cards (`w-32 h-32` thumbnail + `Customize` button), and a 3-column verified reviews grid at the bottom. The migrated view replaced this with a dark gradient header, a `lg:col-span-4` left sidebar (`About` + `Hours` + `Reviews`), and a `lg:col-span-8` right menu grid using `_DishCard.cshtml`.

### Pattern 2: Dropped Custom CSS Classes from `wwwroot/css/input.css`
`wwwroot/css/input.css` contains custom component CSS specifically engineered for the 3 areas flagged by the user (`cards`, `list view`, and `image gallery in dish details page`). The migrated views dropped these custom class names:
1. **Dish Details Gallery & Grid (`input.css` lines 847–872)**:
   - `.dish-detail-grid` (`display: grid; grid-template-columns: 36.5% 1fr; gap: 64px; align-items: start;`)
   - `.dish-gallery-frame-690` (`height: 690px !important;`)
   - `.dish-photo-card-420-520` (`width: 420px !important; height: 520px !important;`)
2. **Browse Dishes List View (`input.css` lines 552–845)**:
   - `.dish-list-container`, `.dish-list-item`, `.dish-list-thumb`, `.dish-list-badge-sale`, `.dish-list-body`, `.dish-list-meta-top`, `.dish-list-kitchen`, `.dish-list-title`, `.dish-list-price-row`, `.dish-list-price`, `.dish-list-original-price`, `.dish-list-meta-bottom`, `.dish-list-rating`, `.dish-list-meta-item`, `.dish-list-actions`, `.dish-list-btn-cart`, `.dish-list-action-icons`, `.dish-list-icon-btn` — **100% omitted** in `Views/Dishes/Index.cshtml` because list view was deleted entirely.
3. **Browse Chefs List View (`input.css` lines 274–550)**:
   - `.chef-list-container`, `.chef-list-item`, `.chef-list-thumb`, `.chef-list-fav`, `.chef-list-body`, `.chef-list-header`, `.chef-list-title`, `.chef-list-subtitle`, `.chef-list-badges`, `.chef-list-rating`, `.chef-list-status`, `.chef-list-pulse`, `.chef-list-bio`, `.chef-list-meta`, `.chef-list-meta-item`, `.chef-list-actions`, `.chef-list-btn-primary`, `.chef-menu-btn`, `.chef-list-btn-chat` — **100% omitted** in `Views/Chefs/Index.cshtml`, which improvised Tailwind flex classes instead.
4. **Starburst Discount Badge (`input.css` lines 167–178)**:
   - `.discount-burst` (`clip-path: polygon(...)`, 12-point starburst badge) — omitted in `_DishCard.cshtml` (which uses a plain `rounded-full` pill instead of the 12-point starburst badge on `main` line 25) and omitted in `Views/Dishes/Details.cshtml`.

### Pattern 3: Precompiled Tailwind v4 (`wwwroot/css/site.css`) Not Rebuilt
`package.json` compiles `wwwroot/css/input.css` into `wwwroot/css/site.css` via:
```bash
npm run css:build
# npx @tailwindcss/cli -i ./wwwroot/css/input.css -o ./wwwroot/css/site.css --minify
```
Because `npm run css:build` was not run after editing the `.cshtml` views, any utility class added in the migrated views that did not already exist in `main` has **zero CSS output** in `wwwroot/css/site.css`.

### Pattern 4: Invented Sample Data, Item Counts, Prices & Image URLs
Instead of unrolling `main`'s exact mock datasets from `store.js` and the partials, the migrated views invented different names, prices, order IDs, and item counts:
- **Kitchen Names**: `Amina's Heritage Kitchen` (`Chef Amina Mansour`) was renamed to `Umm Ali's Kitchen` in `Dishes/*`, `Cart/*`, `Checkout/*`, `Orders/*`, `Customer/*`, `Admin/*`, `Support/*`, and `Chat/*`.
- **Dish Names & Prices**: `Baladi Duck Molokhia with Vermicelli Rice` (`240.00 EGP`, original `280.00 EGP`) was replaced with `Molokhia with Roasted Baladi Chicken` (`195.00 EGP` or `210.00 EGP`).
- **Order IDs**: `#HC-2026-9041`, `#HC-2026-8890`, `#HC-2026-9150` were replaced with `#HC-10492`, `#HC-10488`, `#HC-10411`.
- **Item Counts**:
  - `/Dishes`: Shows **4** dish cards instead of `main`'s **6** dishes (`dish-1` through `dish-6`).
  - `/Chefs`: Shows **4** chef cards instead of `main`'s **5** chefs (`chef-1` through `chef-5`, missing `Mama Nadia's Pastry`).
  - `/Chefs/Details/1`: Shows **3** dishes and **2** reviews instead of `main`'s **4** dishes and **3** reviews.
  - `/Dishes/Details/1`: Shows **2** reviews instead of `main`'s **3** reviews.
  - `/Customer/Favorites`: Shows **2** favorite dishes and **1** favorite chef instead of `main`'s **3** dishes (`dish-1`, `dish-2`, `dish-4`) and **2** chefs (`chef-1`, `chef-2`).

### Pattern 5: Dropped Local Alpine Visual State & Interactive Modals
Several purely visual Alpine interactions that work with local `x-data` (requiring no backend) were stripped or broken:
- **Dish Details 3D Vertical Card Stack & Lightbox**: Stripped `activeImageIndex`, `getCardStyle(idx)`, pointer/wheel drag handlers, right-edge indicator dots, 64px thumbnail buttons, fullscreen zoom lightbox (`<template x-teleport="body">`), and the 3 bottom accordions (`openAccordion`).
- **Browse Dishes Grid/List View Toggle**: Stripped `viewMode: 'grid' | 'list'` from `Views/Dishes/Index.cshtml`.
- **Filter Drawer (`_FilterDrawer.cshtml`)**: Deleted `_FilterDrawer.cshtml` (availability toggle, min rating pills, max prep time pills, dietary tags pills, price range inputs) from `/Dishes` and `/Chefs`.
- **Home Coverflow Active Slide Caption (`_CoverflowCarousel.cshtml`)**: Replaced the reactive caption panel (`selected === 0..5`) with static text for Slide 1 (`Royal Pashas Molokhia & Duck`), so clicking or dragging slides 2–6 never updates the title, description, price, or link below the carousel.
- **Home Thinking Prompt (`_ThinkingPromptInput.cshtml`)**: Stripped `window.initThinkingPrompt` (`status`, `steps`, `answer`, `thinkEnabled` checkbox, and inline streaming answer card).
- **Dish Card Quick View Button (`_DishCard.cshtml`)**: Changed the 3rd hover button (`#eye`) from dispatching `open-quick-view` (which opens `_QuickViewModal.cshtml` loaded in `_Layout.cshtml`) into `<a href="/Dishes/Details/1">`, making `_QuickViewModal.cshtml` unreachable from dish cards.
- **Customization Options Modal (`_OptionsDialog.cshtml`)**: Deleted `_OptionsDialog.cshtml` (which opened when clicking `Add to Cart` on dishes with customization options or clicking `Customize` on `/Chefs/Details/1`).
